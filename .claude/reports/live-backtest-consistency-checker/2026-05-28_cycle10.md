### 🟠 D-2 (MEDIUM, asymmetric gate by-design): CRT cooldown gate live-only

**Locations:** `crypto_alert.py:4304-4311` (live GAP-CRT-2 fix), no equivalent in `backtest.py`.

**Detail:** Cycle-9 GAP-CRT-2 fix (commit 4adcd4f) added a per-direction 30-min SIGNAL_COOLDOWN to the LIVE CRT scan branch. Backtest CRT has no time cooldown — only the per-C1-zone `consumed_h4_crt` mitigation.

**Scenario where it matters:** Two DIFFERENT C1 zones produce same-direction CRT signals within 30 min on the same token. Backtest counts both signals; live blocks the second. Empirically rare given C2 lookback of 6 H4 bars = 24h cycle — but the asymmetry exists. The 5M_SWEEP backtest path also lacks cooldown (5M_SWEEP live applies it at line 2854) so this is a class-wide divergence between live (operator-protection cooldown) and BT (no cooldown).

**Impact:** **Backtest WR is now an UPPER BOUND on live WR** for the cooldown-rejected signals (which historically were marginal-quality back-to-back fires that operator wanted to avoid). Same direction as DR-1: BT optimism.

**Recommended:** Document explicitly as known structural asymmetry in `docs/LIVE_BACKTEST_PARITY_ROADMAP.md` Phase B. Optional: add cooldown to BT for full parity (~5 lines, would slightly reduce BT signal count).

### 🟢 D-3 (LOW, cosmetic): EMA rounding difference between get_trend and _lookup_trend

**Locations:** `indicators.py:11` (`get_trend` via `ema()` returns `round(val, 8)`); `backtest.py:502-514` (`_ema_series` no rounding).

**Detail:** Live's `get_trend` is used for CRT trend_1h via `crypto_alert.py:4276` (`get_trend(_c1h_closed_only)`). Backtest uses `_lookup_trend` → `_ema_series` (no rounding). Both feed into `_trend_from_ema(close, e50, e200)` which compares with `>`. At 8-decimal-place rounding, the threshold-crossing probability of disagreement for crypto prices is effectively zero (~1 in 10^8). **Inert in practice — treat as cosmetic.**

### 🟢 D-4 (LOW, residual edge case from H-NEW-2): Wyckoff slice early-data fallback

**Location:** `backtest.py:1504-1505` slice `[max(0, h4_end-200):h4_end]`.

**Detail:** When `h4_end < 80` (the WYCKOFF_H4_MIN_BARS floor), the slice has fewer than 80 bars → `detect_wyckoff_context` falls back to `TRANSITION`. The outer loop allows `h4_end ∈ [h4_window=~10, n4)` so the first ~70 iterations (early backtest history) will get TRANSITION fallback. Live in this regime would also be data-starved at startup.

**Impact:** Bounded to the first ~3 days of backtest data. Most signals occur at h4_end >> 80. With `BACKTEST_DAYS=365`, this affects <1% of the signal-generation window. **Inert in practice but not strictly identical to live.**

**Recommended:** Add an outer-loop guard `if h4_end < WYCKOFF_H4_MIN_BARS: continue` to make the divergence explicit and skip the early-data TRANSITION-only window. ~2 lines.
