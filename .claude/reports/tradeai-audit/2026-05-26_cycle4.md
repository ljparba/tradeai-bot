## 3. Priority Action List

### CRITICAL — Must fix before LIVE switch (or before next promotion uses these metrics)

- [ ] **C-NEW-1** (Honest Metrics, NEW CRITICAL): `validation.py:592-598` (psr_oos) and `validation.py:617-623` (DSR) pass `n_returns=len(pnl_pool)` while `sr_observed=sharpe_mean` (mean across OOS fold Sharpes from ~`n/K*k ≈ 16` obs each). The PSR/DSR standard-error denominator `sqrt(T-1)` assumes T = number of returns used to estimate `SR_hat`. Using T=43 vs T≈16 inflates `sqrt(T-1)` by ~1.67×, **overstating DSR by ~12pp at the current baseline (~92.5% reported vs honest ~80.5%)**. Verdict can flip PASS→FAIL. Per Bailey & López de Prado 2014 eq. (1)-(2), T must be per-Sharpe observation count. Fix: either (a) pass `n_oos_per_fold = int(n * n_test_groups / n_groups)`, or (b) concatenate OOS returns into a single series and compute a single OOS Sharpe (matches Bailey/LdP convention).

## 5. Executive Summary

The TradeAI v13 system at **8.58/10** is a step BACK from this morning's 9.00, but the regression is **structurally honest**: the multi-agent framework had its first look at the Phase B.1 + Phase C code we shipped today, and it found real issues that an internal review would have missed. No prior fixes regressed. No live-blocking bugs were silently introduced. The decline is entirely attributable to (a) the n=7 sample-size cliff that Phase B.1 produces by design, which collapses the Template dimension's measurability (−2.0pt), and (b) a genuine formula-level error in `validation.py:592-623` (NEW C-NEW-1) that has been latent since Sprint-3 honest metrics shipped but was unmasked when agents re-verified the math against Bailey & López de Prado 2014.

C-NEW-1 is the headline finding. `psr_oos` and `DSR` use `n_returns=len(pnl_pool)=43` as the standard-error denominator, but the Sharpe being PSR-tested is the **mean of OOS-fold Sharpes**, each computed from ~16 observations. The `sqrt(T-1)` term is therefore inflated by `sqrt(42)/sqrt(15) ≈ 1.67×`, **overstating DSR by ~12pp at the current baseline**. The Run-77 DSR=100% claim is partially the result of this inflation; honest DSR is likely closer to ~88%. The verdict gate at `validation.py:650-658` could flip from PASS to MARGINAL or FAIL once corrected. This is the single most important fix in the queue and should be done before any further auto-promotions or operator-driven LIVE-clearance decisions.

FLAW-1 (WFV contaminates held-out window when `HELD_OUT_DAYS > 0`) is harmless today (default 0) but breaks the Phase C design contract — the lockbox's entire value is that it is never touched, and `walk_forward(all_signals)` at `backtest.py:3205` accesses it for decay analysis. S-2a/b (promote_baseline.py held-out gate strips PnL fields + skips n_trials) are real but only matter if the operator opts into the `--held-out-days` auto-promote path. The remaining cycle-3 carry-overs (H-A, H-B, H-F, M-D/E/F, etc.) are status-quo open items that the agents re-confirmed haven't moved.

**Template Calibration −2.0pt** is the most dramatic dimensional change. It is NOT a code regression — `strategy_templates.py` is byte-identical to cycle-3. It is the honest result of Phase B.1's DR-gate filter (Run-78 yields n=7, all in Tier B with `entry_type=MIDPOINT_RECLAIM`). At this sample size the framework cannot stratify, validate, or calibrate. The path forward is either to wait for paper signals to accumulate (the operator's preferred discipline) or to use the live DB (Tier A n=47, Tier B n=80) as the calibration ground truth, treating backtest as a forward-overfit guard rather than a tier calibrator.

**LIVE GO/NO-GO: NO-GO.** Three binding blockers:
- **C-NEW-1** must be fixed and the verdict gate re-validated before any honest-metrics-driven decision can be trusted. ~30 min of work + a re-run.
- **0/30 paper signals** — the unmovable statistical-evidence gate.
- **H-F** (BTC feed Telegram) — operational visibility for LIVE 24/7 ops.

Paper trading is **unconditional GO**. The underlying signal-generation code is sound. Run-78 is held as the operational baseline with documented n=7 caveats; the operator should let paper signals accumulate before re-running any explorer sessions or considering Phase D.

**Single highest-impact improvement:** Fix C-NEW-1 in `validation.py:592-623`. This is a 30-line edit (change the PSR/DSR caller to either concatenate OOS returns or pass per-fold T), one re-run against Run-78 to capture the honest DSR, then update CROSS_REF + baseline_pin.json with the corrected numbers.
