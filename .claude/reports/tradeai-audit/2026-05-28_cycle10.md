## 3. NEW HIGH / SERIOUS Findings (4)

### T-1 (template-tier) — Tier A MSS=MEDIUM bar too loose; empirical separation lost

**Severity:** 🟠 HIGH (template-quality / pre-LIVE blocker)
**Location:** `strategy_templates.py:478` (Tier A definition)

The new Tier A definition (FVG + MSS≥MEDIUM) yields **63.9% WR (n=180)** on the full backtest dataset (1945 closed CRT signals). Tightening to FVG + MSS=HIGH yields **72.5% WR (n=80)** with Wilson 95% CI [61.9%, 81.1%] — a statistically separated top tier that does NOT overlap with Tier B/C confidence intervals.

The current looser definition admits ~100 additional MSS=MEDIUM FVG signals at lower WR, diluting Tier A's discriminating power.

**Fix:** 1-line edit at `strategy_templates.py:478` changing the MSS bar from `MEDIUM` to `HIGH`.

### T-2 (template-tier) — Tier B is the WORST tier; empirical ordering INVERTED

**Severity:** 🟠 HIGH (template-quality / pre-LIVE blocker)
**Location:** `strategy_templates.py:527` (Tier B definition)

Full-population analysis (n=1945 closed CRT signals):

| Tier bucket | n | WR% | Wilson 95% CI | avg realR |
|---|---|---|---|---|
| **A_new (FVG + MSS≥MEDIUM)** | 180 | **63.9%** | [56.7, 70.6] | +0.498 |
| C_OB (OB other MSS) | 980 | 55.9% | [52.8, 59.0] | +0.347 |
| **B_new (OB + MSS=HIGH)** | 776 | **51.0%** | [47.5, 54.5] | +0.224 |

**Empirical ordering is A > C > B, not A > B > C.** Within OB-only signals: MSS=HIGH = 51.0% WR but MSS=MEDIUM = 56.9% (n=902). MSS quality is mis-modeled for OB signals — Tier B's "high-quality MSS" filter selects the *worse* sub-population.

The commit's own validation slice (`f776d82`, n=95) noted "no strict A>B>C monotone ordering." At the full population it generalizes — Tier B is structurally inverted.

**Fix:** 1-line edit at `strategy_templates.py:527` flipping B's MSS bar from `HIGH` to `MEDIUM`. After flip, Tier B should rise to ~57% WR territory and the empirical ordering recovers to A > B > C.

### RISK-GAP-NEW-1 (risk-mgmt) — CRT Tier A/B bypasses Phase 5A safety checks in LIVE mode

**Severity:** 🟠 HIGH (LIVE-blocking, PAPER-inert)
**Location:** `crypto_alert.py:4384-4393` (CRT LIVE block) vs `crypto_alert.py:3236-3248` (5M_SWEEP Phase 5A call)
**Introduced by:** commit `4bfa534`

The 5M_SWEEP path calls `evaluate_template_status()` which enforces INSUFFICIENT_SAMPLE (50 closed trades), PAUSED_BY_CIRCUIT_BREAKER (rolling WR ≥ 55%), and DAILY_CAP_REACHED gates. The CRT LIVE block only reads the static `template_live_allowed` from the signal dict — set at signal creation from the hardcoded `live_allowed=True` registry value. `evaluate_template_status()` is never called for CRT signals.

Additionally, `TIER_DAILY_LIVE_CAPS` in `config.py:257-262` has no entries for `CRT_A_FVG_ALIGNED`, `CRT_B_OB_HIGH_MSS`, `CRT_B_FVG_RELAXED`, or `CRT_C_OB_DEFAULT`. Even if the Phase 5A call were wired, the cap lookup would return 0 and the function would incorrectly declare every CRT signal PAPER_ONLY.

**Worst case in LIVE mode:** operator flips to LIVE with 0 closed CRT trades; CRT Tier A signal fires; Telegram is sent; position is taken with no WR-history basis. INSUFFICIENT_SAMPLE, CIRCUIT_BREAKER, and DAILY_CAP all silently bypassed.

**Mitigation today:** PAPER mode makes this inert. Manual LIVE-flip requires `LIVE_MODE_CONFIRMED=YES`, `YOUR_CAPITAL` set, and honest-metric clearance gates (CPCV≥60%, DSR≥95%, N≥30 closed) which CRT currently fails.

**Fix:**
1. Add CRT template IDs to `TIER_DAILY_LIVE_CAPS` (`config.py:257-262`): `"CRT_A_FVG_ALIGNED": 3, "CRT_B_OB_HIGH_MSS": 2, "CRT_B_FVG_RELAXED": 2, "CRT_C_OB_DEFAULT": 0`
2. Replace the static `_tmpl_ok` read at `crypto_alert.py:4385` with a call to `evaluate_template_status(conn, _tmpl_id, "UNKNOWN")`.
