## 3. NEW HIGH / SERIOUS Findings (3)

### H-NEW-1 (honest-metrics) — `cumulative_min_trials` read-only stub; DB wipe broke selection-bias correction

**Severity:** 🟠 HIGH — DSR understates selection bias right now (DB has been wiped per git status)
**Locations:** `backtest.py:3839-3861` (read), `scripts/promote_baseline.py:237-244` (read), `scripts/validate_baseline_held_out.py:78` (read) — **no write site exists anywhere**

The C-D cycle-5 fix added READ paths for `bot_state['cumulative_min_trials']` to protect `n_trials_for_dsr` from being artificially lowered after a DB wipe. The intent was to persist the maximum-ever-seen distinct-config count so it survives a wipe. **The write half was never implemented.** Every `INSERT OR REPLACE INTO bot_state(...)` site (`adaptive_engine.py:662/1282/1785`, `compute_cross_config_sr_std.py:276`, `backtest.py:3953`) writes other keys — none write `cumulative_min_trials`.

**Impact:** After any DB wipe (TradeAI.db is currently `D` in git status), `_cumulative_min_trials = 0`. `max(_candidate, 0)` is a no-op. The actual `_candidate` after a wipe = `0 + 0 + 1 = 1`. DSR computed with `n_trials=1` → `expected_max_sharpe(1, std) = 0.0` → selection-bias correction completely removed. A strategy that tried 50+ configs before the wipe appears to need only 1 trial's correction.

**Fix:** Add the write half at `backtest.py:3957` after `latest_cpcv_verdict` write — 5 lines. Also mirror in `promote_baseline.py` and `validate_baseline_held_out.py`.

**Bias direction:** Optimistic (overstates DSR after a wipe). Live data-quality risk, not a crash.

### H-NEW-2 (live-bt-consistency) — Wyckoff window asymmetry — C-3 fix introduced new live↔BT divergence

**Severity:** 🟠 HIGH (inert today, becomes HIGH on filter flip)
**Location:** `backtest.py:1490` post-C-3 vs `crypto_alert.py:921` live

The cycle-8 C-3 fix changed `detect_wyckoff_context(c4h)` to `detect_wyckoff_context(c4h_win)` — but `c4h_win` is only 12 bars in the backtest scan loop. `detect_wyckoff_context` has `min_bars=80` (`crt_engine.py:838-845`) and returns `TRANSITION` when the window is too short. Result: **every CRT signal in backtest now gets `entry_type=H4_CRT_*_TRANSITION`**, while live (which passes full 200+ bar cache) emits real ACCUMULATION/DISTRIBUTION/MARKUP/MARKDOWN labels.

**Impact:**
- Inert at the signal-generation layer right now (`WYCKOFF_PHASE_FILTER=off`)
- Corrupts OGD per-phase bootstrap attribution: backtest_signals' phase column is meaningless
- Would zero out ALL backtest CRT signals if `WYCKOFF_PHASE_FILTER=loose` is flipped (since loose rejects TRANSITION)
- Once explorer tunes the filter (search space includes `loose`), this becomes a critical correctness bug

**Fix:** Inside the loop, expand the Wyckoff input slice to at least `min_bars` (e.g. `c4h_for_wyckoff = c4h[max(0, h4_end-200):h4_end]`) while preserving the no-lookahead invariant (only bars ≤ `h4_end-1`).

### H-NEW-3 (ict-logic ESCALATION) — CRT path has no MIN_SL_PCT / MAX_SL_PCT / ICT_MIN_RR_GATE clamps

**Severity:** 🟠 HIGH (escalated from cycle-8 MEDIUM M-1 based on new live evidence)
**Location:** `crt_engine.py:compute_crt_trade_economics` vs `ict_engine.py:759, 786` for 5M_SWEEP

**Live empirical evidence:** Signal #2 (TON SELL) carries `sl_pct=-6.18%` — more than 2× the structural ceiling `MAX_SL_PCT=3.0%`. The 5M_SWEEP path would reject this via `compute_ict_trade_plan` at `ict_engine.py:759, 786`. The CRT path doesn't apply MIN_SL_PCT, MAX_SL_PCT, or ICT_MIN_RR_GATE clamps — relies entirely on the operator's `CRT_TP1_MODE=min_1r` discipline + the BEW economic gate to keep things sane.

Today's mitigation is `template_live_allowed=0` for CRT (Telegram suppressed in LIVE) — but the moment that flag flips, a 6%+ SL CRT signal would reach the operator's Telegram and pose real capital risk.

**Fix:** Add `MIN_SL_PCT` / `MAX_SL_PCT` / `ICT_MIN_RR_GATE` enforcement inside `compute_crt_trade_economics` — ~15 lines.
