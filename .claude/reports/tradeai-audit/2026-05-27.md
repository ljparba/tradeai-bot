## 2. NEW CRITICAL Findings (3)

### C-1 (Multi-agent: ict-logic, live-bt-consistency, data-pipeline, config) — Live CRT scanner is SILENTLY INERT

**Severity:** 🔴 CRITICAL — production state diverges from dashboard for 24+ hours
**Files:** `crypto_alert.py:1766` + `crypto_alert.py:3780-3788` + `crt_engine.py:357-359`
**Verification:** `sqlite3 data/signals.db "SELECT COUNT(*) FROM signals"` returns **0** at audit time, 28h after CRT-only mode activated.

**Root cause:**
- `fetch_binance_candles()` at `crypto_alert.py:1766` returns dict with key `"timestamps"`.
- `crt_engine.detect_h4_crt` at `crt_engine.py:357-359` requires `required_keys = {"opens","highs","lows","closes","times"}` — singular `times`, not `timestamps`.
- Comment at `crypto_alert.py:3780` says `"Inject 'times' if missing (some fetch paths use 'time')"` — the engineer knew about this — but no injection code was ever written.
- Result: `detect_h4_crt` silently returns `None` on every cycle. `scan_h4_crt_for_token` returns `(None, None, "no_setup")` indistinguishable from a legitimate no-setup outcome.
- Backtest is unaffected (`backtest.py:367` builds dict with `"times"` directly).

**Why it survived audits + tests + bot startup:**
- Tests use synthetic candle dicts built with `"times"` key directly — they never go through `fetch_binance_candles`.
- Yesterday's audits ran BEFORE this was the active code path (commits `9e335c2` + `6c9137e` shipped same day — bots restarted after audits).
- Bot heartbeat reports normal cycles. No error log entry. Pure silence.

**Fix (2 lines):**
```python
# crypto_alert.py:3780 — before scan_h4_crt_for_token call
if "times" not in _c5m and "timestamps" in _c5m:
    _c5m = {**_c5m, "times": _c5m["timestamps"]}
if "times" not in _c4h and "timestamps" in _c4h:
    _c4h = {**_c4h, "times": _c4h["timestamps"]}
```

**Classification:** NEW FINDING. M24-isomorphic (silent runtime divergence between live and backtest). Same bug class as yesterday morning's `LIVE_LIQUID_HOURS` ImportError.

### C-2 (ict-logic, live-bt-consistency) — Live CRT consumes FORMING (non-closed) 4H+5M bars

**Severity:** 🔴 CRITICAL — non-repaint invariant violated for the live path
**Files:** `crypto_alert.py:3776-3777` vs `crypto_alert.py:2450-2454`

**Root cause:** The canonical 5M_SWEEP path applies `[:-1]` to slice off the in-progress bar (`crypto_alert.py:2450-2454`). The CRT live path passes the raw `STATE[token]["candles"]["4h"]` directly to `scan_h4_crt_for_token` — INCLUDING the live, forming bar at index `-1`. Once C-1 is fixed, CRT setups will be detected on bars that haven't closed yet, producing live signals that disagree with backtest (which only sees closed bars).

**Note:** This issue is downstream of C-1 — currently inert because no CRT signal fires at all. Once C-1 is fixed, C-2 becomes active.

**Fix:** Apply `[:-1]` slice symmetrically in the CRT path, matching the 5M_SWEEP precedent.

### C-3 (backtest-bias-detector) — Wyckoff lookahead in `backtest.py:1469`

**Severity:** 🔴 CRITICAL — corrupts ALL Wyckoff-tagged entry_type labels in `backtest_signals`
**Files:** `backtest.py:1469` (`detect_wyckoff_context(c4h)`)

**Root cause:** The H4 outer walk-loop correctly uses a windowed slice (`c4h_win`) but `detect_wyckoff_context(c4h)` is called with the full 365-day dataset, not the window. Inside the function, `closes[-window_n:]` always reads the final 120 bars of the entire dataset — so a January 2025 signal gets a Wyckoff label computed from December 2025 future candles.

**Consequences:**
- Run #140 Test B's −5.22pp WR result for WYCKOFF_PHASE_FILTER=strict is **lookahead-contaminated** — the true effect (positive or negative) is unknown.
- All Wyckoff phase tags in `entry_type` (e.g. `H4_CRT_OB_ACCUMULATION`) on `backtest_signals` are corrupted — retroactive per-context SQL analysis is unreliable.
- The explorer's CRT search space (just shipped today) includes `WYCKOFF_PHASE_FILTER ∈ {off, loose}` as a tunable. The next explorer session would produce lookahead-biased WR for `loose` trials.

**Fix (one line):** Change `backtest.py:1469` from `detect_wyckoff_context(c4h)` to `detect_wyckoff_context(c4h_win)`.

**Live path verified UNAFFECTED:** Live's `scan_h4_crt_for_token` calls `detect_wyckoff_context(c4h)` on a real-time-bounded fetched cache — naturally no future bars exist. The bug is purely at the backtest call site.
