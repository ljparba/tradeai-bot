## STILL OPEN GAPS (carried from cycle-8, unchanged)

### GAP-CRT-1: CRT Path Has No ICT_MIN_RR_GATE (1.5R Minimum)

**Files:** `crypto_alert.py` (`scan_h4_crt_for_token`), `backtest.py` (`run_backtest_token_h4_crt`)

**Status:** STILL OPEN. Both the live and backtest CRT paths skip the explicit `rr1 < ICT_MIN_RR_GATE=1.5` check. The BEW gate (bew > 0.60) provides a backstop that blocks rr1 ≤ ~0.67. With `CRT_TP1_MODE=min_1r`, TP1 is at minimum 1R from entry, so the current ship config has a practical floor of rr1=1.0 on all CRT signals.

**Severity assessment:** The cycle-8 severity of SERIOUS is unchanged. The practical impact is low in the current `min_1r` config because TP1 ≥ 1R is guaranteed by the TP1 mode — actual rr1 below 1.5 would require the SL to be wider than the TP1 target, which the BEW gate filters. However, this is a configuration-dependent safety property rather than a code-level hard gate. If `CRT_TP1_MODE=dynamic` is ever re-enabled (with c1_opposite as TP1 target), rr1 could be as low as 0.67 without any block.

**Recommendation:** Add `if econ["rr1"] < ICT_MIN_RR_GATE: rej["crt_rr_gate"] += 1; continue` in `run_backtest_token_h4_crt()` after the economics check, and a parallel reject in `scan_h4_crt_for_token()`. This would make CRT consistent with 5M_SWEEP and protect against config drift.

**File:** `crypto_alert.py` — `scan_h4_crt_for_token()` never reads/writes `STATE[token]["last_signal_times"]`

**Severity assessment:** SERIOUS maintained. In PAPER, the operator can observe both signals without consequence. In any LIVE-adjacent scenario (even manual execution of paper signals), receiving two SELL alerts 3 minutes apart on the same token is operationally confusing.

**Live/BT symmetry:** The backtest CRT path also has no cooldown gate — `run_backtest_token_h4_crt` scans all H4 bars without a COOLDOWN_BARS equivalent. Any pair of adjacent H4 CRT setups on the same token can fire in consecutive bars (4h apart minimum, but multiple setups detected in the same bar scan can appear simultaneous in the backtest timeline). This symmetry means backtest WR is not distorted — it's a design choice to allow back-to-back CRT signals rather than an error.
