### MEDIUM-1 — Live and backtest CRT scanners compute 4H bias via different code paths

**File:** `crypto_alert.py:817-820` (LIVE) vs `backtest.py:1429` (BACKTEST)

**LIVE path:**
```python

    bias_4h = get_ict_4h_bias(c4h["closes"], c4h["highs"], c4h["lows"])

```

**BACKTEST path:**
```python

# → bisect.bisect_right(ind4h["times"], ts_ms - 1) → last 210 bars → get_ict_4h_bias()
```

Both eventually call `get_ict_4h_bias()`, but:
- LIVE passes the FULL c4h cache (up to 400 bars per `TIMEFRAMES["4h"]["limit"]` at `config.py:163`) — uses ALL bars to compute bias.
- BACKTEST slices to the LAST 210 bars at the entry timestamp via `_lookup_4h_bias`.

`get_ict_4h_bias` (`ict_engine.py:409`) computes EMA50/EMA200 on whatever it's given. Different bar-window sizes → potentially different EMA values → potentially different bias label at boundary cases.

**Severity:** MEDIUM (defensible asymmetry — both paths use a sensibly-large window; bias rarely flips on the last 200 vs 400 bars, but it CAN at trend inflection points).

**Recommended fix:** Use the same 210-bar slice in live to match backtest's `_lookup_4h_bias` semantics:
```python

    _N = min(len(c4h["closes"]), 210)
    bias_4h = get_ict_4h_bias(
        c4h["closes"][-_N:], c4h["highs"][-_N:], c4h["lows"][-_N:],
    )
else:
    bias_4h = "NEUTRAL"
```

**Cross-ref classification:** NEW FINDING (post-Session-3 — Session 3 brought the live CRT scanner online; the prior 5M_SWEEP path uses `get_ict_4h_bias` at `crypto_alert.py:2468` with a different parameter pattern entirely).

## CRT-specific concerns — direct answers

### Q: Dealing-range gate behavior on CRT signals
**A:** The CRT scanner (in both live `scan_h4_crt_for_token` and backtest `run_backtest_token_h4_crt`) does NOT call `compute_dealing_range`, does NOT check `dr_location`, and does NOT consult `config.dealing_range_gate`. The DR gate is bypassed entirely for CRT signals — which is correct, since CRT has its own structural validation (C1 range + sweep wick + MSS within MSS_HORIZON).

Additionally, both `LIVE_DEALING_RANGE_GATE` and `BACKTEST_DEALING_RANGE_GATE` are currently `False` (Phase B revert 2026-05-26), so even the 5M_SWEEP scanner doesn't apply it. CRT_FEATURE_SCORES correctly tags CRT signals with `dr_location="UNKNOWN"` (crypto_alert.py:919) so OGD doesn't try to learn DR signal from CRT trades.

**Verdict:** Consistent.

### Q: Does the LIVE_BIAS_4H_GATE=strict gate use the same `_lookup_4h_bias` helper?
