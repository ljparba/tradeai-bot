### NEW-1 (adaptive) — F-1 SMT wiring is INERT at the adaptive learning layer (cycle-10 fb30114) — MEDIUM

**Severity:** MEDIUM — net-neutral now, but misleading commit claim and a missed learning opportunity
**Classification:** NEW FINDING
**Locations:**
- `adaptive_engine.py:144-152` (FEATURES list — 6 entries, no `smt_*`)
- `adaptive_engine.py:1854-1907` (extract_ict_feature_scores — no SMT parameter)
- `strategy_templates.py:441-629` (CRT tier scorers _score_crt_a/_score_crt_b_ob_high/_score_crt_c — no `smt_confirmed` consumption)

**Discrepancy:** commit `fb30114` body claims:
> "Effect: SMT bonus stops being dead code. Operator can now measure true SMT-CRT correlation and decide whether to gate later."

But the SMT bonus referenced is in the **5M_SWEEP** tier scorers (`strategy_templates.py:213-214`, `:285-286`, `:347-348` — Tier A/B/C for 5M signals). The legacy `_score_tier_a/_score_tier_b/_score_tier_c` functions DO read `smt_confirmed` as a `+0.10` bonus. With `ENABLE_5M_SWEEP=0` (current operator config), those 5M tier scorers **are never evaluated** — `scan_token` is short-circuited at `crypto_alert.py:~3624`.

The CRT tier scorers (`_score_crt_a/_score_crt_b_ob_high/_score_crt_c`) — which ARE evaluated for the current operator config — do not consume SMT in scoring. And `extract_ict_feature_scores` has no SMT feature dimension at all, so the OGD gradient pipeline is also blind to SMT.

**Impact:**
- F-1 fix is correctly wired at the **storage layer** (signals.db rows now carry real `smt_type` + `smt_confirmed` instead of NONE/0 stubs).
- F-1 fix is **alive at the dashboard layer** (operator can split CRT WR by `smt_confirmed=1` vs `0` in queries).
- F-1 fix is **inert at the adaptive layer** — OGD doesn't learn anything from SMT, CRT tier scoring doesn't bonus on SMT, and the 5M scoring that does is gated off.
- This is not a regression — pre-fb30114, SMT was a `0/NONE` stub everywhere; post-fb30114 it's computed honestly but no consumer uses it for live decisions.

**Recommended fix (Phase 5C, low priority while CRT-only):**
- Option A (cheap, informational): leave as-is. Document this in `docs/comprehensive/CROSS_REF.md` as KNOWN STRUCTURAL "SMT informational only for CRT signals".
- Option B (adaptive): Add `smt_strength` as a 7th OGD feature dimension. Score = 1.0 if `smt_confirmed=True` else _SCORE_FLOOR. Re-normalise DEFAULT_WEIGHTS. Requires schema migration of `feature_scores_json` + bootstrap reseeding.
- Option C (template-level): Add a `+0.05` SMT bonus to CRT tier scorers, mirroring the 5M tier-A pattern. Smaller blast radius — only affects tier classification (not OGD), and only changes the score (not the live_allowed flag).

**Recommendation:** start with Option A + B if SMT-CRT correlation in paper soak proves meaningful (n>=30).
