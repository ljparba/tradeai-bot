#### M-CYCLE10-2 (live↔BT asymmetry) — BTC token's own CRT scan uses BTC as its own SMT reference
**Severity:** MEDIUM (data-quality / silent inert noise)
**Location:** `crypto_alert.py:4284-4288` (live) vs `backtest.py:3820,3847` (BT)
**Detail:** The backtest explicitly passes `btc_c5m=None if token == "BTC" else btc_c5m_ref` when scanning BTC's own CRT setups (no self-comparison). The live CRT scanner has no equivalent guard — it always passes `_btc_c5m_for_smt` even when `token == "BTC"`. Effect: when BTC sweeps its own swing low, `detect_smt_divergence` compares BTC's `recent_min` to BTC's own `prior_low`, which by definition CANNOT confirm divergence (BTC always swept itself if it just had a sweep). The result is `smt_confirmed=False` with reason "BTC also swept SSL" — silently inert, but the live record carries SMT=False for BTC CRT signals while the backtest carries SMT="no BTC reference". Live↔BT field-value asymmetry on BTC token's signals.
**Bias direction:** None (both outcomes are SMT=False, just with different reason strings). Live signals will look slightly different from BT signals for BTC trades when slicing per `smt_type` reason.
**Fix:** In `crypto_alert.py:4284`, gate the assignment on `token != "BTC"`:
```python
_btc_c5m_for_smt = None if token == "BTC" else (
    STATE["BTC"]["candles"].get("5m", {})
    if "BTC" in STATE and ...
)
```
The 5M_SWEEP path has the same blind spot (see crypto_alert.py:2956-2958) — both should be patched together for consistency, but only the CRT path is in the cycle-10 scope.
