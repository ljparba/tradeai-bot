## 2. NEW Findings

### T-1 (HIGH) — Tier A's MSS≥MEDIUM bar admits weak FVG signals; stricter MSS=HIGH yields +8.6pp WR
**Severity:** 🟠 HIGH — calibration finding
**Location:** `strategy_templates.py:478` (`_score_crt_a`)

Current Tier A: `confluence==FVG AND mss_quality >= MEDIUM` (2/2).

Cross-tab from full CRT closed-signal population:

| Tier A definition | n | WR% | avg realR | Wilson CI |
|---|---|---|---|---|
| **Current (FVG + MSS≥MEDIUM)** | 180 | 63.9% | +0.498 | [56.7, 70.6] |
| **Stricter (FVG + MSS=HIGH only)** | 80 | **72.5%** | +0.568 | [61.9, 81.1] |
| Excluded MEDIUM-MSS slice | 100 | 57.0% | +0.441 | [47.3, 66.2] |

The MEDIUM-MSS slice (n=100) drags Tier A's WR by **8.6pp** and contributes nothing the OB-MSS=HIGH bucket can't already represent. Stricter Tier A would also produce a **non-overlapping CI vs Tier B/C** — finally a statistically separated top tier.

**Tradeoff:** signal count drops 180 → 80 (~55%), but 80 signals is still ≥30 (LIVE-clearance bar) and well above any usability floor.

**Fix:** change `:478` from `QUALITY_RANK.get(mss_quality, 0) >= QUALITY_RANK["MEDIUM"]` to `mss_quality == "HIGH"`. Update template description string accordingly.

### T-2 (HIGH) — Tier B (OB+MSS=HIGH) is empirically the WORST tier, not the middle tier
**Severity:** 🟠 HIGH — definitional regression
**Location:** `strategy_templates.py:502-547` (`_score_crt_b_ob_high`)

Counter to the redefinition commit's "MSS=HIGH compensates for OB" thesis, the full-population cross-tab shows:

| OB MSS quality | n | WR% | avg realR |
|---|---|---|---|
| OB + MSS=HIGH (Tier B) | 776 | **51.0%** | +0.224 |
| OB + MSS=MEDIUM | 902 | 56.9% | +0.372 |
| OB + MSS=LOW | 78 | 44.9% | +0.054 |

Within the OB universe, **MSS=MEDIUM outperforms MSS=HIGH by 5.9pp** (n=902 vs 776 — both large samples; this is not a small-sample artifact). The MSS quality dimension that drives FVG signals' edge does NOT drive OB signals' edge. The Tier B definition fundamentally mis-models OB behavior.

**Hypothesis (cross-domain for ict-logic-validator):** OB's MSS=HIGH bucket may be biased toward extreme/exhaustion sweeps where the H4 candle range got drilled hard, and the strong subsequent MSS marks a regime change reversal that hurts trend-continuation entries. Worth investigating directly.

**Fix options:**

| Option | Edit | Tier B becomes |
|---|---|---|
| A (minimal) | Flip B's MSS bar to `MEDIUM` | OB + MSS=MEDIUM, 902 signals, 56.9% WR — beats Tier C (55.9%) marginally |
| B (radical) | Drop MSS gate entirely from Tier B | OB + any MSS, ~1756 signals, 53.8% WR — bigger but undifferentiated |
| C (semantic) | Redefine B as "best OB" via session+bias filter | OB + (NY_AM_KZ OR ASIA_KZ) + bias-aligned — needs grid search to pick |

Recommend Option A as a fast empirical fix; Option C as a 1-week explorer task once H-NEW-2 (Wyckoff window asymmetry) is patched.

### T-5 (MEDIUM) — 4H bias bonus rewards directional regime, not confluence
**Severity:** 🟡 MEDIUM — bonus is capturing a spurious correlation
**Location:** `strategy_templates.py:482-484` (and parallel in `_score_crt_b_ob_high`)

Direction × 4H bias cross-tab:

| Direction | bias_4h | n | WR% |
|---|---|---|---|
| BUY | BULLISH | 959 | 44.2% |
| BUY | BEARISH | 124 | 45.2% |
| SELL | BEARISH | 1348 | **63.6%** |
| SELL | BULLISH | 127 | 52.8% |

The +0.10 bias-aligned bonus is supposed to capture "trade with the trend". But the data shows BUY signals lose at 44-45% **regardless of bias**, and SELL signals win at 53-64% **regardless of bias**. The bonus is structurally picking up a **directional regime bias** (the 365d sample is during a crypto downtrend where shorts have an edge), not "this confluence is aligned with HTF context".

**Cross-domain note:** This is data conditional — once the regime changes (uptrend phase), the asymmetry could flip. The bonus formula treats both directions symmetrically, which is correct for a structural strategy. But on this calibration sample, it's not adding tier discrimination.

**Recommended action:** keep the bonus structure (it's the right shape) but **drop it from the tier score's float component until the dataset spans at least one full regime cycle**. Right now it's adding noise to the score sort order. Alternatively, normalize the bonus by per-direction base rate.

## 6. Proactive Improvement Suggestions

**Suggestion 1:** Add a "Tier A+" template for FVG + MSS=HIGH + NY_AM_KZ — the data-driven elite slice.
**Why:** Currently zero combinations of (FVG + MSS=HIGH + NY_AM_KZ) exist in the calibration set (sample is small), but the sub-slices each show 70%+ WR. A Tier A+ marker would flag any future signal hitting all three as a candidate for higher position-sizing (operator discretion). Tier A+ would NOT change live_allowed gating; it would be purely informational.
**Impact:** MEDIUM — adds a long-term operator-discretion signal layer
**Effort:** Simple — 1 new scoring function + 1 registry entry, ~30 LOC

**Suggestion 2:** Replace fixed-threshold tier calibration with percentile-rank tier calibration.
**Why:** Current tiers are defined by binary feature thresholds. After N≥500 closed CRT signals, switch to "Tier A = top 20% by predicted-WR using a logistic blend of FVG/MSS/session/bias features fit on training window." The percentile re-calibrates monthly and adapts to regime changes — would have caught the LONDON_KZ inversion automatically.
**Impact:** HIGH — turns tier system from a hard-coded heuristic into a self-calibrating scoring layer
**Effort:** Complex — new module, schema for "tier_calibration" history, monthly recalibration cron, A/B test against current scheme

**Suggestion 3:** Move tier scoring INTO the OGD weight learning loop.
**Why:** Today tiers are descriptive (post-classification); they don't influence learning. If each tier carried its own OGD weight subspace, the bot could learn (a) Tier A's weights converge tighter to "trust this signal" and (b) Tier C's weights stay flat to "this is exploratory". Currently both tiers feed the same per-token weight vector — a Tier A win and a Tier C win have the same gradient impact.
**Impact:** HIGH — would unlock per-tier confidence scaling for live position sizing
**Effort:** Complex — schema change + adaptive_engine.py refactor

**Suggestion 4:** Run an explorer session pinned to `EXPLORER_SEARCH_SPACE=crt-tier` that varies the Tier A MSS bar, the Tier B MSS bar, and the bonus weights — to find the tier definition that maximizes the WR delta between A and the others while preserving n≥30 in A.
**Why:** The current redefinition was a single-shot hypothesis update on n=95. An automated grid would find the locally-optimal cut without the operator hand-tuning.
**Impact:** HIGH for tier discrimination
**Effort:** Medium — extend `scripts/autonomous_explorer.py` SEARCH_SPACE_CRT_TIER block + ~30 LOC
